## 项目目标

本项目研究裸 P15 及其二硫环变体与人源 CK2α、CK2α′催化亚基的潜在直接结合。
目标是在不提供结合位置约束的条件下发现候选结合位点，验证位点和姿态对随机采样、受体构象及计算方法的稳健性，再进行序列优化和动力学验证，最终形成值得实验检验的候选环肽和结构假设。

项目不预设以下结论：

- P15 一定结合 CK2α/CK2β 界面；
- P15 一定直接抑制 CK2 催化活性；
- 最优候选一定同时覆盖 CK2α 和 CK2α′；
- 对接、评分或 MD 能够直接证明细胞效应或抗肿瘤疗效。

候选 site 定义完成后，才将其映射到 CK2β 界面、ATP 区域、底物相关区域和全酶环境。功能区域重合是后验解释证据，不是首轮搜索约束或命中标准。

## “效果好”的项目内定义

“效果好”不能直接作为未定义的计算目标。Vela 将其拆成可验证的证据层级：

| 层级 | 项目内含义 | Vela 能否回答 |
|---|---|---|
| 位点可重复 | 同一表面区域被多个独立 seed 和受体构象反复找到 | 可以 |
| 姿态可信 | 全原子精修后形成非冗余构象簇，且没有明显化学或几何问题 | 可以 |
| 序列表现 | 变体相对原始 P15 在多个模板和目标状态上表现稳定 | 可以做相对比较 |
| 动态稳定 | 多条独立 MD 轨迹支持界面和环肽构象保持 | 可以 |
| 亚型行为 | 候选可能同时覆盖两个亚型或偏向其中一个 | 可以提出计算假设 |
| 直接结合与功能抑制 | 是否真实结合、是否影响 CK2 活性或 CK2β 结合 | 必须实验验证 |
| 细胞与抗肿瘤作用 | 递送、细胞进入、真实靶点、毒性和疗效 | 必须通过后续实验验证 |

因此，Vela 的计算终点是“具有明确化学结构、预测结合 site、亚型特征、动态证据和实验优先级的候选环肽”，不是“已经证明有效的抗肿瘤药物”。

## 研究范围与结论边界

| 范围内 | 范围外或不能直接推出 |
|---|---|
| 裸 P15 与孤立 CK2α/CK2α′催化亚基的潜在直接结合 | Tat 等递送结构对构象、进入细胞和结合的影响 |
| 无位置约束的全表面 site 发现 | 真实细胞靶点的最终确认 |
| 多构象、多 seed 的结构复现 | docking score 到实验亲和力的直接换算 |
| P15 pose 和序列变体的相对计算排序 | 仅凭单一评分函数宣布变体优于原始 P15 |
| 多重复 MD 稳定性比较 | 短时间未解离等同于高亲和力 |
| CK2β、ATP 和全酶环境的后验映射 | 仅凭空间重合宣布功能抑制或抗肿瘤机制 |

如果后续研究 Tat–P15、其他递送构建体或细胞活性，应建立独立的分子定义、实验问题和结论边界，不能将裸 P15 的结果直接外推。

## 核心证据原则

1. **按科学问题组织阶段。** 阶段不再等同于某个软件或脚本。
2. **使用“无位置约束”而非“无偏”。** 全表面搜索没有显式 site 先验，但仍受势能、训练数据、初始构象和有限采样影响。
3. **先发现，后解释。** 正式 apo/apo-like site 冻结前，不利用 CK2β、ATP 或实验环肽位置调整 P15 site 排名。
4. **独立 seed 才是主要随机重复。** 同一轨迹中的 replica、帧或大量相似 decoy 不能冒充独立证据。
5. **不同证据类型分层保存。** 主集合盲发现、结合态复现、方法阳性控制、已知位点引导任务、MD 和功能映射不得合并成未经定义的命中率或总分。
6. **局部精修不发现新 site。** FlexPepDock 只验证已有粗略复合物在局部能否形成合理全原子构象。
7. **序列优化不得早于位点定案。** 没有稳健 site 和多个精修模板时，不启动正式 P15 变体筛选。
8. **不同失败机制不可用总分互相抵消。** 化学错误、位点漂移、模板依赖、动态不稳和亚型目标不符应分别判定。
9. **结论强度不得超过最弱关键证据。** 计算候选必须保留不确定性并明确实验缺口。

## 证据类别与隔离规则

| 证据类别 | 来源 | 回答的问题 | 是否计入正式盲发现支持度 |
|---|---|---|---|
| 主发现证据 | 每个 target 独立 run 中 apo/apo-like 受体的 P15 全表面搜索 | P15 在该 target 的未结合受体上反复访问哪些 site？ | 是，但不跨 target 累加支持度 |
| 受体状态复现 | P15 对去配体结合态受体的全表面搜索 | site 是否依赖配体诱导受体构象？ | 单独统计，不与主集合直接相加 |
| 方法阳性控制 | 实验环肽对去配体受体的回对接或局部恢复 | 方法能否找回已知正确界面和姿态？ | 否 |
| 已知位点兼容性 | 将 P15 放入实验配体区域后做局部精修 | P15 在物理上能否适应该界面？ | 否，必须标记为 guided |
| 动态验证 | 原始 P15 和变体的多重复 MD | 候选 pose 是否具有动态保持能力？ | 否，是后续验证层 |
| 功能解释 | 与 CK2β、ATP、全酶及其他区域叠合 | 候选可能影响什么功能？ | 否，是后验注释 |
| 实验证据 | 直接结合、活性、竞争、细胞和体内实验 | 候选是否真实有效？ | 不属于当前计算证据 |

任何报告都必须保留上述类别字段。不能把“apo 两个 seed + 结合态两个 seed + 一个 guided pose”写成“五份盲命中证据”。

## 有配体复合物的完整使用方式

每个有配体结构从同一只读来源派生多个不同对象，身份和结果不得互相覆盖：

```text
原始实验复合物
├── 完整实验参考：保留受体、原配体及经审计的结构组分
├── 去配体结合态受体：保留受体结合态构象，用于 P15 全表面复核
├── 原配体全局回对接：验证盲对接方法能否找回已知 site
├── 原配体跨构象对接：验证方法在 apo/apo-like 受体上的表现
├── 原配体局部恢复：验证全原子局部精修和评分行为
└── P15 已知位点任务：单独检验 P15 对实验 site 的结构兼容性
```

| 用法 | 处理 | 科学用途 | 解释限制 |
|---|---|---|---|
| 完整复合物参考 | 不删除原配体，保留只读副本 | 定义实验接触、热点、受体构象和必要结构水 | 不提供 P15 盲搜约束 |
| 原配体全局回对接 | 删除原配体，从全表面重新搜索同一配体 | 方法资格阳性控制 | 不能算作 P15 结果 |
| 原配体跨构象对接 | 将原配体对接到匹配的 apo/apo-like 受体 | 检查未结合受体上的方法性能和构象依赖 | 需要保证配体化学可被工具正确表示 |
| P15 对去配体受体盲搜 | 删除原配体，P15 搜索整个表面 | 检查阶段二 site 的受体状态复现 | 与 apo 主证据分层统计 |
| P15 已知位点局部任务 | 生成处于实验 site 的粗略 P15 pose 后局部精修 | 判断盲搜未命中时是否属于采样问题或结构不兼容 | 不能计作盲命中 |
| 原配体局部恢复 | 从实验 pose 的受控扰动开始局部精修 | 验证 FlexPepDock 是否能保留或恢复已知姿态 | 只评价局部协议 |
| 最终叠合和功能映射 | 比较 P15、原配体、CK2β 和全酶空间关系 | 解释潜在竞争、可达性和功能关联 | 不能替代功能实验 |

### 具体结构的优先职责

- **4IB5/Pc**：Pc 是与 P15 长度和二硫环拓扑最接近的 CK2 实验配体，优先用于 CK2 相关全局回对接、跨构象对接、局部恢复和 P15 已知位点兼容性控制。
- **9FBM/9FBI–FMP37**：同一配体结合两个亚型，优先用于 CK2α/CK2α′结合态受体差异和 P15 跨亚型复核。若 FMP37 的非标准化学结构不能被当前工具可靠表示，则只进行结构比较，不强行将其作为回对接配体。
- **6YZH、9FBL、6Q4Q**：用于检查不同环肽尺寸和化学类型导致的受体构象敏感性，不在首轮证据充分时无差别全部运行。

方法参数不得只用 CK2 复合物反复调到命中。通用参数应先用与 P15 长度和二硫环拓扑相近的外部公开基准校准，再将至少一个 CK2 复合物保留为体系相关验证对象。

## 五阶段总体流程

```text
阶段一：P15 与结构数据准备
        ↓  化学、下载、审计和制备产物完整
阶段二：全表面方法资格 + 单 target 多构象盲发现
        ↓  candidate site 与排名冻结
阶段三：结合态复现 + 独立结构复核 + 全原子局部精修
        ↓  形成可用于设计的多模板证据
阶段四：多状态 P15 序列优化
        ↓  形成有限且可追溯的 MD 候选
阶段五：多重复 MD 验证 + 功能映射 + 实验优先级
        ↓
形成待直接结合、功能、细胞和后续体内实验验证的候选环肽
```

### 工作内容

#### P15 化学定义

- 固定序列 `CWMSPRHLGTC` 和 1–11 编号。
- 显式定义 Cys1–Cys11 二硫键、标准 L-手性、N/C 端、目标 pH、His7 微状态、其他可变质子化残基和净电荷。
- 记录每个决定的实验来源、计算假设和不确定性。
- 若原始资料无法唯一确定端基，预先声明主状态和有限的化学敏感性状态；不同状态使用不同 chemistry ID，结果不得混合。
- 验证全局对接、局部精修、序列优化和 MD 对同一拓扑的表达一致性。

#### 受体审计与制备

- 审计 `3Q04`、`3QA0`、`5YF9`、`5Y9M` 的实体、作者链、构建体范围、突变、缺失残基、缺失原子、替代构象、晶体接触和实验组分。
- 区分“实际构建体末端”和“最后一个有坐标的残基”；不得把未解析区段之前的最后坐标残基机械地设为带电自由末端。
- 水、离子、结晶添加剂和共价状态逐类审计，不能统一全部删除。
- 原始 mmCIF 只读保存；所有制备结构必须具有父级结构、处理步骤和文件哈希。

- 如果 blind 和 guided 两条独立路径收敛到相同 site 和相近 pose，作为一致性增强证据；如果不一致，应保留采样、受体状态或结构兼容性不确定性。
- 执行阶段一预先声明的组成、长度、环拓扑或电荷匹配控制，检查候选 site 是否只是对一般性黏性环肽都给出相似结果。

### 分支 D：后验结构环境检查

- 将阶段二和精修后的 site 映射到 CK2β、ATP、底物相关区域及其他已知功能位置。
- 将代表 pose 叠合到 `4MD7`、`1JWH` 和必要的 `4DGL`，检查全酶空间可达性、CK2β 排斥和四聚体环境。
- CK2α′全酶环境使用基于实验 CK2α 全酶排布建立的模型时，必须明确标记为同源复合物模型而非实验结构。
- 当前自动报告接触数、最小距离和对齐 RMSD，不在全酶碰撞阈值尚未校准时自动宣布 CK2β 竞争；功能结论仍需要实验验证。

### 候选分级

| 等级 | 判定含义 | 后续用途 |
|---|---|---|
| 强候选 | 主集合多 seed 发现、跨构象复现、局部精修成簇，并获得独立受体状态支持 | 优先进入序列优化 |
| 中等候选 | 主集合发现和局部精修可靠，但跨状态或跨构象证据有限 | 保留少量模板并明确不确定性 |
| 构象特异候选 | 只在某类受体状态中稳定出现 | 作为特定受体状态假设研究 |
| 引导假设 | 盲搜未稳定发现，但在实验 site 的 guided 精修中结构合理 | 独立报告，不能升级为盲发现主候选 |
| 不支持 | 主要依赖单 seed、精修后普遍跑偏、拓扑错误或存在明显结构问题 | 不进入正式序列优化 |

具体数值标准在阶段一通过独立控制校准后冻结，不能在看到喜欢的 P15 site 后反向调整。

### 主要产物与放行条件

主要产物包括结合态复现报告、全原子 decoy 清单、精修构象簇、blind/guided 分组、候选证据卡、多模板序列优化起点和全酶环境报告。

只有具有阶段二主发现身份、足够独立支持、多个合格全原子模板并通过结构环境审查的候选，才能作为阶段四正式设计模板。guided-only 假设可以保留研究，但不得与主候选共用结论标签。

## 阶段四：多状态 P15 序列优化

### 目标

在固定 Cys1–Cys11 二硫环的条件下，以阶段三通过复核的多个 site、亚型、受体构象和精修 pose 为模板，寻找相对原始 P15 更稳健的候选序列。

### 设计目标

当前项目采用 `single_supported_target`：阶段二和阶段三仍分别评价两个亚型，但每次阶段四设计运行只选择一个获得结构支持的亚型。若两个亚型都形成合格模板，则分别运行两条独立轨道，最终候选池取两条轨道的并集，不要求同一序列同时覆盖两个亚型。

| 轨道 | 正向目标 | 准入规则 |
|---|---|---|
| CK2α 支持轨道 | 改善 CK2α 的多个合格模板 | 不要求 CK2α′同时改善，也不要求主动削弱 CK2α′ |
| CK2α′支持轨道 | 改善 CK2α′的多个合格模板 | 不要求 CK2α 同时改善，也不要求主动削弱 CK2α |

单次运行必须只包含一个亚型的正向模板且不包含反向模板；不存在结构基础的轨道不因形式完整而强行运行。命中任一轨道只表示获得该亚型的计算支持，不等同于已证明细胞或抗肿瘤有效。

### 工作内容

- 固定 Cys1、Cys11、二硫键和已确认的端基化学；其他固定位置必须有结构或实验依据，不能继承 legacy 对 P5、G9 或 His 的默认限制。
- 原始 P15 必须在每个 site、模板、亚型和计算协议中作为共同基线。
- 第一层完整枚举 2–10 位的全部合法单点替换；当前允许 19 种非 Cys 标准 L-氨基酸，每个位置排除 WT 后共形成 162 条确定性单点序列，不依赖生成模型是否采到。
- 在每个冻结模板和独立 seed 上对 WT/候选使用相同局部邻域做成对固定骨架侧链重排；相同 WT 输入通过 `wt_context_id` 只计算一次。主趋势为候选减 WT 的 `paired_dG_separated_delta`，单个极端 seed 只作诊断，不再作为一票否决。
- 只从通过单点门槛的不同位置替换提出有限二/三点组合；组合必须作为完整序列在全部模板上重新计算，不把单点可加性当作组合结论。资源截断在二/三点突变间分配预算并平衡位置组合覆盖，避免按序号偏向 N 端；未获预算只表示 deferred，不代表失败。
- 首轮组合只生成并实际重算双突变。三突变及以上只能从通过柔性门槛的同代父序列生成增加、撤销或替换一个位点的一步邻域；迭代父序列与阶段五 MD 队列使用独立选择状态。
- 多代候选保存 `generation`、全部直接父序列、每个父代编辑和祖先 candidate ID；同一后代由多个父序列到达时只计算一次但保留全部来源。默认累计突变上限为 5，而每代候选预算在父序列、编辑位置和编辑类型间平衡；超预算候选只标记 `resource_deferred`。
- `md_selected` 只表示进入阶段五资源队列，不代表动态或实验成功。production 下一代父序列仍应结合阶段五和实验记录显式决定；在这些结果尚未建立前，多代入口只形成可追溯计算提案，不能据此声称获得更优治疗候选。
- 初筛后最多让配置数量的候选进入第二层 FlexPepDock 柔性复核。起点固定取最小的已冻结初筛 seed，避免按候选 score 挑起点；随后使用另一组明确 seed 产生柔性 ensemble。
- 柔性复核分别比较通过结构 QC 的 `reweighted_sc` 和 `I_sc` 中位数，并检查每模板成功 seed 数、decoy 通过率、碰撞、界面接触、受体位移、起始接触保持和 site 位移。同一 Rosetta 能量函数的两个字段不是两种独立物理方法，因此仍需阶段五 MD 和实验。
- 每条候选动态生成 His pose 编号并保持配置声明的 HIE；不能为绕过 tautomer 处理而禁止新增 His。Cys1/Cys11、端基、二硫键、净电荷和所有结构哈希随候选保存。
- 报告净电荷、疏水/芳香残基、最长连续疏水段、Met、脱酰胺和天冬酰亚胺 motif 等透明事实；没有项目实验校准前，这些描述量不作为自动“药物性”淘汰门槛。
- 不沿用 legacy 的 BoltzGen 核心路线。标准 ProteinMPNN/BoltzGen 对当前短二硫环肽没有足够的项目级资格证据；以后只有专门环肽模型通过独立验证后，才可作为组合提案来源，且生成频率、rank 和 refold 坐标不能作为亲和力证据。
- 不沿用 legacy 的 `simple_cycpep_predict` 游离态放行。当前环是侧链二硫键而不是主链首尾成环；游离预组织和构象代价转入阶段五的无受体多重复 MD，并结合实验溶解性、聚集、稳定性和合成结果判断。

### 主要产物

- 带目标轨道、化学状态和来源的候选序列库；
- 带代次、直接父序列、父代编辑和完整祖先链的多代候选谱系；
- 原始 P15 与所有候选的单亚型多模板对照，以及两个独立亚型轨道间的后验比较；
- 供阶段五无受体 MD 使用的候选化学合同和序列事实；
- 通过、失败和仅因资源未推进的候选状态；
- 有限、可追溯的阶段五 MD 队列。

其中阶段四直接输出的是复合物柔性 ensemble、透明序列事实和 MD 输入结构；游离环肽构象证据由阶段五补齐，不能为了让阶段四表面上“完整”而使用未资格化的方法。

### 放行条件

- 候选相对原始 P15 的优势不依赖单一模板、单一 seed、单一 score 字段或一次极端值；
- 候选满足固定二硫环、化学状态和设计轨道合同；
- 所有关键失败门槛和资源截断均已记录；
- MD 队列同时保留原始 P15、重点变体和必要的对照，不只保留计算最低分变体。

## 阶段五：MD 稳定性验证与实验优先级

### 目标

通过一致体系构建和多条独立轨迹，检验原始 P15 及重点变体的复合物是否具有可重复的动态保持能力，并结合结构和功能映射形成实验优先级。

### 工作内容

- 对原始 P15、各单亚型支持轨道的候选、事后显示跨亚型支持的候选和必要对照进行模拟。
- 比较亚型时使用一致的力场、水模型、离子条件、体系制备、模拟时长和分析方法。
- 每个体系运行多个独立重复并使用不同初始速度；单条轨迹不能形成最终结论。
- 预先定义 pose 保持、接触占有率、界面距离、P15 主链与受体局部 RMSD、二硫环构象、受体局部变化和界面水等指标。
- 保留 blind 来源和 guided 来源，不能因为 guided pose 在 MD 中稳定就改写其发现身份。
- 将动态代表结构重新映射到 CK2β、ATP、全酶环境和两个亚型的对应 site。
- 不把有限时长内未解离解释为实验高亲和力，也不从稳定性直接推断酶抑制或细胞疗效。

### 主要产物

- 每个体系和重复的不可变运行合同、轨迹索引和质量报告；
- 预设动态指标的逐重复和跨重复汇总；
- 原始 P15 与变体、CK2α 与 CK2α′之间的同层级比较；
- 候选证据总卡、已知限制和实验优先级；
- 直接结合、亚型行为、CK2β 竞争、酶活性、递送和细胞实验的建议验证问题。

### 完成条件

- 主要判断不依赖单条轨迹或单一初始 pose；
- 支持和不支持主要结论的重复均被展示；
- 最终优先级能追溯到化学状态、主发现 site、复核证据、序列设计和 MD；
- 报告明确区分计算假设和待实验确认的结合、功能及抗肿瘤问题。

## 阶段反馈与回退规则

```text
阶段一方法或化学不合格
└── 留在阶段一，不用扩大采样掩盖输入问题

阶段二 site 不收敛
└── 按冻结规则增加 seed、预算或主集合受体审计，不直接挑最低分 pose

阶段三精修普遍跑偏或状态复现失败
└── 降低 site 等级，返回阶段二补采样或保留为构象特异/引导假设

阶段四变体只适配单一模板
└── 淘汰或返回候选构建，不送入 MD

阶段五变体动态不稳
└── 返回阶段四产生新序列；若原始 pose 本身不稳，返回阶段三重新审查模板
```

回退不是覆盖旧结果。每轮运行必须使用新 run ID 并保留前一轮证据和失败原因。

## 项目完成标准

项目只有同时满足以下条件才视为完成：

| 类别 | 完成标准 |
|---|---|
| 输入完整 | P15 化学状态和所有受体身份、链、构建体、变异及处理决定可追溯 |
| 方法合格 | 全局搜索和局部精修通过与正式结果隔离的阳性、阴性和拓扑控制 |
| 主发现完整 | 每个目标 target 均在自己的 run 中完成全部 apo/apo-like 构象的多 seed 全表面搜索 |
| site 可复现 | candidate site 来自独立 seed，并评估同亚型跨受体构象稳定性 |
| 证据隔离 | 主发现、结合态复现、方法控制、guided、MD 和功能映射具有不同身份 |
| 结合态复核 | `4IB5`、`9FBM`、`9FBI` 完成适用的参考、控制和去配体受体复核角色 |
| 姿态可信 | 主候选由多个全原子精修模型支持，且没有未解决的关键结构问题 |
| 序列比较有效 | 变体相对原始 P15 的优势跨模板复现，并符合明确的亚型目标 |
| 动态验证完成 | 原始 P15、重点候选和必要对照完成一致的多重复 MD |
| 功能解释不过界 | CK2β、ATP、Tat、细胞和抗肿瘤结论没有超出相应证据层级 |
| 流程可重跑 | 所有结果可由声明配置、输入哈希、代码和工具版本及 seed 重新生成 |

## 重构原则

本项目执行重构，不执行 legacy 迁移：

- `legacy/` 只作为只读审计材料，不参与新代码导入、运行或依赖解析；
- 不保留旧 CLI、旧 `config/*.toml`、旧编号目录、旧 TSV schema 或旧输出路径的兼容层；
- 不复制旧 `scripts/` 到新包，也不继承旧 CABS 安装补丁、机器绝对路径和化学假设；
- 不为旧测试维持旧接口，测试应按新数据合同和科学规则重写；
- 只有经过重新论证的算法思想可以在新实现中重写，例如来源哈希、运行 manifest、seed 独立支持、site/pose 证据分离和 FlexPepDock 几何质控；
- 不迁移 legacy 结果或运行状态。当前 legacy 不包含可作为正式科学证据的完整结果集；
- 新实现从 `src/vela/` 建立唯一正式路径，不存在新旧双轨。

## 代码架构与目标项目结构

`src/` 是 Python 的标准 source layout 根目录，用于隔离可安装包与配置、数据、文档和测试；它不是一个业务模块。真正的职责划分发生在 `src/vela/` 内部。代码不使用 `stage1/`、`stage2/` 这样的编号目录，因为后续阶段需要复用前面形成的稳定领域对象，编号会把依赖方向变成“阶段之间相互调用”。顶层业务包使用稳定的科学职责命名：

| 包 | 科学职责 | 依赖规则 |
|---|---|---|
| `core/` | 哈希、原子写入、错误和外部数据类型收窄 | 不依赖任何具体科学阶段 |
| `config/` | 组合四份包内 TOML、四份项目 TOML、环境变量和领域对象 | 可以依赖 core 与领域模型，不承载业务计算 |
| `preparation/` | 阶段一的化学定义、结构获取、审计和基础制备 | 只依赖 core，不依赖后续阶段 |
| `discovery/` | 阶段二全表面发现和 site 聚类 | 依赖阶段一稳定产物，不反向修改 preparation |
| `validation/` | 阶段三结合态复现、控制、局部精修和结构环境复核 | 消费冻结的 discovery 结果 |
| `design/` | 阶段四多状态序列优化 | 消费通过结构复核的多模板证据 |
| `dynamics/` | 阶段五 MD 体系、运行与分析 | 消费冻结候选，不承担序列搜索 |

当前只创建已经有真实实现的包。`discovery/` 已含放行、规划、规范证据和 site 分析实现；`validation/` 已建立阶段三完整链路，`design/` 已建立阶段四完整链路；`dynamics/` 只在阶段五开始时创建。禁止用空目录和占位接口预先搭框架。单个工作流内部继续按“领域模型、纯解析/转换、报告、编排”拆分；CLI 入口不得包含科学逻辑。

### 配置、数据和结果边界

| 内容 | 位置 | 规则 |
|---|---|---|
| 包内工作流默认参数 | `src/vela/resources/` 的四份阶段 TOML | 唯一工作流默认值，随包安装 |
| P15/CK2 项目输入 | `configs/` 的四份 TOML | `common.toml` 保存共享事实，三份阶段文件只保存实际项目覆盖，不复制完整默认参数 |
| P15 与受体数据 | `data/` | 保存原始输入、审计和可追溯制备产物，不保存配置或运行目录 |
| 阶段二主发现运行 | `outputs/runs/<run-id>/` | 每个 run 不可变，保存 manifest、配置快照、输入哈希、seed 和结果索引 |
| 阶段二资格运行 | `outputs/discovery/qualifications/<run-id>/` | 每个 run 只对应一个 target，控制与先导证据隔离于正式支持度 |
| 阶段三运行 | `outputs/validation/<category>/<run-id>/` | control、replication、handoff、guided 和 refinement 按证据职责分目录，不与主发现混算 |
| 阶段四初筛 | `outputs/design/screens/<run-id>/` | 单点与组合轮次分别使用不可变运行目录和 WT 配对结果 |
| 阶段四柔性复核 | `outputs/design/finalists/<run-id>/` | 保存候选 ensemble、不可补偿门槛、序列事实和阶段五队列 |
| 临时文件 | `temp/` | 可随时删除，不能成为正式输入 |
| 研究事实 | `docs/research.md` | 保存结构事实、来源、限制和待核查项 |
| 项目方向与状态 | `docs/plan.md` | 保存阶段、证据规则、门槛状态和决策记录 |
| 参数索引 | `docs/config.md` | 说明两个配置来源、全部可调参数和有意固定的代码合同 |

配置加载优先级从低到高为包内默认值、外部配置、环境变量和命令行参数。外部配置的相对路径相对于配置文件所在目录解析。外部工具路径不得硬编码个人主目录；运行时应记录实际解析路径、版本和可用时的文件哈希。

阶段二主发现进入 `outputs/runs/`，阶段三按证据职责进入 `outputs/validation/`。内部结构数据优先保留 mmCIF；只有在外部工具要求时才生成 PDB、PDBQT 等边界格式，并记录转换来源。
